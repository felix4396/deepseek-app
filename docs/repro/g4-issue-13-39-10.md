### 根因（文件:行）
- 主因：`g4-before/rspack.config.ts:8` `const targets = ['chrome >= 105', …]` 把语法下限写死在配置里，`package.json` 没有 `browserslist`，且没有任何地方校验"这个数字必须覆盖 WebView 83"。
- 次因 1：`g4-before/index.html` 没有 ES5 启动守卫 → 解析失败时无任何用户可见提示（静默白屏）。
- 次因 2：语法降级只解决"能不能解析"，**救不了运行时 API**：`Object.hasOwn(93)/at(92)/structuredClone(98)` 由 `src/polyfills/legacy.ts` 补，但 `String.prototype.replaceAll(85)` 一直没人补（`legacy.ts` 里没有 `installReplaceAll`）。
- 次因 3：`.frame` 用 `var(--app-viewport-height,100dvh)` 当唯一高度来源（修复前 `dist` CSS），Chrome 83 上 var 默认值非法 ⇒ 整条 `height` 失效。

### 方案（现状：A/B 已在 #33 落地，剩下 C 的收尾）
1. **保留**现状（`package.json:9` browserslist `chrome >= 83` 作为唯一来源 + `rspack.config.ts:30-34` 读它并 fail-fast + `target:'browserslist'` + mermaid 单独 swc 降级 + lightningcss 同源 targets）——这是对的骨架，别动。
2. **补 `replaceAll`**：`src/polyfills/legacy.ts` 增加 `installReplaceAll()`（`String.prototype.replaceAll`，参数为字符串或 `Symbol.replace` 对象，用 `indexOf` 循环实现，保持"存在即跳过"的幂等约定），并加进 `installLegacyPolyfills()` 列表；`tests/unit/legacy-bundle-target.test.mjs` 的 API 覆盖断言数组里加 `'replaceAll'`。
3. **CSS 残余降级**（低风险、可后置）：`:has(+ul)` 那 15 条是外边距微调，`@container` 那条是隐藏小标签，建议加 `@supports selector(:has(*))` 包裹或直接接受偏差并在 `docs/COMPAT-MATRIX.md` 里记一条"低内核间距差异"。
4. **回归命令**：
   ```bash
   pnpm build && pnpm check:legacy && pnpm type && pnpm lint
   env -u http_proxy -u https_proxy pnpm test
   node _scratch/analyze-bundle.mjs dist        # 期望：Chrome 85+ 项仅剩 Intl.Segmenter(有守卫) 与 replaceAll(补完后为 0)
   ```
5. **未测边界**：WebView 83.0.4103.106 真机/mermaid 实绘/mermaid 之外的 `async` 分片是否在低内核首次交互时才炸（懒加载分片的失败只会表现为"点了没反应"）。

## #39 门禁拦不住"漏发 polyfill"（核心缺陷，已实证）

### 可验证主张
1. 主张 A：`check:legacy` 只看**语法记号 + dvh**，完全不看运行时 API 与 polyfill 是否进产物。
2. 主张 B：因此一个**把 polyfill 摘掉的产物**能拿"合格"、exit 0 —— 门禁对 beta.8 那一类事故是零拦截。
3. 主张 C：门禁也没有"polyfill 必须在入口脚本里"的概念（`async/` 下的分片同样满足任何字符串存在性检查）。

### 根因（文件:行）
- `scripts/check-bundle-syntax.mjs:454-478`（`main()`）：判定集合 = 词法 + AST + dvh，**没有**"polyfill 是否进了产物/是否在入口脚本"这一项。

- `tests/unit/legacy-bundle-target.test.mjs:63-76`（用例 C）：只断言源码，不断言产物。
- `docs/RELEASE-MANUAL.md`：发版清单里没有 `npm run check:legacy`，`RELEASE.md:3` 还把发版指向该手册——门禁写了但没接线。

### 方案（可直接落地的补丁）
在 `scripts/check-bundle-syntax.mjs` 里加第三类检查，并让它进 `fails`：

```js
// ---- 新增：运行时补齐是否真的进了产物，且必须在入口脚本里（issue #39） ----
const POLYFILL_FLAG = '__DEEPSEEK_LEGACY_POLYFILL__'

const checkPolyfill = (distDir) => {
  const problems = []
  // 1) 入口脚本必须来自 index.html 的 <script src>，且每个入口都必须自带补丁
  const html = readFileSync(path.join(distDir, 'index.html'), 'utf8')
  const entries = [...html.matchAll(/<script[^>]+src="([^"]+)"/g)]
    .map((m) => m[1].replace(/^\.?\//, ''))
    .filter((src) => src.endsWith('.js'))
  if (entries.length === 0) problems.push({ kind: 'no-entry-script', file: 'index.html' })
  for (const src of entries) {
    let code = ''
    try { code = readFileSync(path.join(distDir, src), 'utf8') } catch { /* 下面统一报 */ }
    if (!code.includes(POLYFILL_FLAG)) {
      problems.push({ kind: 'polyfill-not-in-entry', file: src })
    }
  }
  // 2) 补丁不许只存在于 async 分片：否则首帧没装补丁，照样炸
  const asyncHits = walkFiles(path.join(distDir, 'static', 'js', 'async'), '.js')
    .filter((f) => readFileSync(f, 'utf8').includes(POLYFILL_FLAG))
  if (asyncHits.length) problems.push({ kind: 'polyfill-split-into-async-chunk', file: asyncHits[0] })
  // 3) 语法下限的单一来源仍是 package.json（顺带把"被改回去"也卡住）
  const pkg = JSON.parse(readFileSync(path.join(ROOT, 'package.json'), 'utf8'))
  if (!(pkg.browserslist ?? []).some((t) => /^chrome\s*>=\s*83$/.test(t))) {
    problems.push({ kind: 'browserslist-floor-missing', file: 'package.json' })
  }
  return { entries, problems }
}
```
`main()` 里并在 `fails` 里加上 `polyfill.problems.length`，输出一行 `polyfill：入口脚本 N 个、缺失 M 个、只在分片里 K 个`，失败时同样 `exit 1`。

配套两件事（缺一不可）：
1. **自测必须证明"真会红"**：把这次实验产物固化成一个 fixture（`tests/fixtures/dist-no-polyfill/`，只需 `index.html` + 一个 3 行的假入口 js），加一条单测断言 `check-bundle-syntax.mjs tests/fixtures/dist-no-polyfill` 退出码为 1；否则将来改坏了也没人知道。
2. **接进发版**：`docs/RELEASE-MANUAL.md` §4 四项人工核对后追加第 5 项 `pnpm check:legacy`，并把 `RELEASE.md:3` 的"四项"改"五项"；`package.json` 的 `check:legacy` 已存在（第 15 行），无需新增脚本。

### 每格怎么判（三种结论的判定规则）
| 结论 | 判定方法 | 不许写成 |
| --- | --- | --- |
| **确实失败** | 复现路径固定 + 至少 2 次一致 + 有截图/日志/`adb logcat` 里可指认的报错（如 `SyntaxError: Unexpected token =`、`TypeError: x.replaceAll is not a function`） | "看起来不行" |
| **通过** | 同一路径在低内核上跑通 + 截图 + 关键交互（发送/滚动/取消/导入）都点过 | "打开不白屏" ≠ 通过 |
| **不可判定** | 设备没到位 / WebView 版本被商店更新后与镜像不符 / 复现路径依赖外部服务 | "应该没问题" |

### 逐 API 的必测项（建议直接抄进矩阵）
1. **首帧**：冷启动到输入框可交互；对照 `dist/index.html` 的守卫提示（`__DEEPSEEK_COMPATIBILITY_ERROR__`）必须为 undefined。
2. **`Object.hasOwn` 路径**：发送一条消息 → 流式渲染（19 处调用集中在 `main`）。
3. **`.at()` 路径**：消息列表滚动 + 代码块高亮（28 处）。
4. **mermaid**：渲染一张流程图 + 一张时序图 → 这是 **replaceAll 唯一必炸点**，API30 上预期 `确实失败`（除非先补 replaceAll），API31+ 预期通过。
5. **弹层高度**：模态/确认框在软键盘弹起后是否仍可见（dvh/vh 差异）。
6. **`:has()`/`@container` 偏差**：markdown 标题与后续列表的间距、`.reason` 小标签是否溢出（`通过` 但记录视觉差异，按 ISSUE-STANDARD 属"带边界关闭"）。
7. **API31 已知 3 项硬失败**（issue 评论记录，需在矩阵里保留原结论并复验）：弹窗手势滑动失效（adb 也滑不动）、取消后表单被清空、URL 导入报"文件不完整"。这 3 项与语法/polyfill 无关，属独立 bug，不要在 #10 里当"兼容性差异"糊过去。

### 明确边界
- 本小节**没有**跑任何模拟器/真机，全部是静态判据 + 已记录的评论证据；矩阵里每一格必须由设备执行方补"截图/日志/WebView 版本"三件套后才能从 `未实测` 改成 `通过/确实失败/不可判定`。
- 不做的事：装模拟器、起多台设备、并发重构建。
- 事故复述（防再犯）：上一轮在 API31 上点过"提交"，Capacitor 把 fetch 转成原生 CapacitorHttp 导致页面拦截失效，真的发出去了带「请忽略」的自测工单。矩阵执行阶段**禁止对真实服务点提交类按钮**。
